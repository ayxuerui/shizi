Spike — hanzi-writer quiz mode (library, not hand-rolled)

Why this spike exists: the hand-rolled canvas spike (/pencil-input/) hit a series of real bugs (hover drawing, buttons-timing race, resize-clearing-canvas) and one still unresolved. Rather than keep debugging throwaway code, this tests the same real question — does Apple Pencil input work well, is palm rejection OK, does fast/paused writing behave — through hanzi-writer, a mature (MIT, 4.9k★, npm-published Sept 2025) library built on the same Make Me a Hanzi data we already have license-cleared. Its quiz() mode does stroke tracing with input handling that's been in production for years — if this has the same bugs, that's real information; if it doesn't, we just saved ourselves from shipping hand-rolled code for something a library already solved.
Try this, and tell me what happens:
  1. Tap "Animate" on any card first, to see the stroke animation (this is the same capability as the /stroke-animation/ spike, via the library).
  2. Tap "Quiz", then trace each stroke with Apple Pencil, resting your palm on the screen as before. Any stray marks from palm contact?
  3. Write the strokes fast, back-to-back, the way that broke the hand-rolled spike. Does every stroke register?
  4. Pause between strokes, then continue. Does it still register correctly?
  5. Note: mistake/hint feedback is deliberately visible in the log below (not on the character itself) for OUR testing purposes only. The design decision for the real product is to log fully but show a 4-year-old no visible correctness feedback — that's a config flag (showHintAfterMisses: false, already used below on the character itself), not a rebuild.
